# Blue Orange Plan

A progam is a large organization which manages and runs projects within the company spread between different domains, teams, and multi-functional teams.

One of the key activity of the program is to manage the requirements coming into the program by different stakeholders in a defined format called the "Blue Plan". The projects within the program submits their individual plans on completion of these requirements in the so-called "Orange Plan".

## Blue Plan
A set of requirements being fed into the program which specifies certain needs along with the owners of these requirements and also the date at which these needs need to be satisfied. These requirements are written from the point of view of the customers and are therefore written in human language, are incomplete and sometimes overlapping with other requirements. Blue Plan is not mutable or editable. They are considered something which gets satisfied at a broad level.

## Orange Plan
An orange plan is a submission of the project plan with key milestones identified in different forms. In case of a digital transformation program they will be "Business Releases" or BRs which will communicate to the program when certain capabilities will be available to be deployed into the company through different domains or groups of people.

There is a need to create a tool which allows program managers to manage and bring this "Blue" and "Orange" plan together into a single set of views which can allow program managers to generate views of validation of cascade of requirements and verification of satisfaction of these requirements through the orange plan project milestones. This combined view of the two plan is called the "Blue-Orange Plan".

## Blue-Orange Plan
Some of the key features of the Blue Orange Plan which are as follows:
1. Many Blue Plan items can be satisfied by Many Orange plan items. i.e. 
    -  There could be one Blue Plan requirement which is providing inputs to many Orange Plan items.

    - There could be an orange plan project which is partially satisfying many Blue Plan requirements

    - There could be One Blue Plan item which is uniquely being satisfied by one Orange plan items.

    - There could be a gap in the existing set of orange plan items which is do not satisfy a given blue plan requirement


2. A Blue plan item provides a need date for satisfying the requirements.
    - This need date can be the end date at which the requirement has to be deployed.

    - All the orange plan business releases and milestones have to be within the blue plan requirement date. If an orange plan business release date goes past a need date it is considered as a "gap" in the blue-orange plan.





# Purpose 
A Tool to manage program management data and generate views of different project and their interdependencies through a web portal.
